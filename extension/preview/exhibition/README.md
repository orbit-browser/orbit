# Orbit 결선 부스 현수막 7장

족자 현수막 950 × 2,380mm 5장과 455 × 2,380mm 2장이다.
확장 빌드에 포함되지 않는 로컬 미리보기이며 실제 사용자 기록을 쓰지 않는다.
행사는 2026-11-03~05, 출력 파일 확정 목표는 10월 30일이다.

```sh
cd extension
SHOT_SCALE=2 node preview/capture-shots.mjs     # 카드 속 페이지 화면(처음 한 번, git 제외)
pnpm preview:ui --port 5203
# http://127.0.0.1:5203/preview/exhibition/
```

## 부스 배치

정면에서 왼쪽부터 아래 순서다. 중앙 세 장은 CHAOS → ORBIT → TECHNOLOGY다.
크기·순서·벽 구분은 `booth.ts`에서 관리한다.

| 번호 | 벽 | 내용 | 크기(mm) |
|---|---|---|---|
| 1 | 왼쪽 앞 | Orbit 브랜드 띠 | 455 × 2,380 |
| 2 | 왼쪽 | USE — 쓰는 법과 기록을 다루는 원칙 | 950 × 2,380 |
| 3 | 가운데 | CHAOS — 흩어진 탐색 | 950 × 2,380 |
| 4 | 가운데 | ORBIT — 세션과 페이지 갤러리 | 950 × 2,380 |
| 5 | 가운데 | TECHNOLOGY — 구조·실측·비교 | 950 × 2,380 |
| 6 | 오른쪽 | TEAM — 세션 공유·측정 방법 | 950 × 2,380 |
| 7 | 오른쪽 앞 | Orbit 브랜드 띠·QR 빈 칸 | 455 × 2,380 |

같은 벽의 기둥 간격은 기본 40mm다. 미리보기에서 벽 사이 160mm는 벽을 구분하기 위한 표시다.

## 보기

- `부스 7장 / 가운데 벽 / 1~7`: 전체 배치 또는 장별 확대.
- `화면 맞춤 / 25% / 50% / 100% / 실제 크기`: 100%는 1mm를 1px로 그린다.
  실제 크기는 CSS mm 기준이며 모니터에서 자로 잰 크기를 보장하지 않는다.
- `안전 여백`: 위·옆 50mm, 아래 80mm. 안내선은 인쇄에 나오지 않는다.
- `애니메이션`: CHAOS 카드의 움직임. `인쇄용 정적 모드`는 움직임과 갤러리 조작을 끈다.
- ORBIT 갤러리: 끌기·스와이프, 초점 상태에서 ← →, 카드 클릭, 위 막대의 ↑ ↓ 세션 전환(제주 → MV3 → Qdrant).
  조작 단추와 안내는 화면에서만 보이고 인쇄·정적 모드에는 없다. 머리글 번호(01 USE … 05 TEAM)는 벽 순서와 같다.

보기 옵션은 주소에 남는다. 예: `?view=4&zoom=0.5&still=1&session=0&page=2`. `variant=span`은 실제 화면 시안(아래)이다.
`session`은 `content.ts`의 `GALLERY_SESSION_IDS` 순서, `page`는 가운데 카드의 0부터 시작하는 번호다.
기존 3장 시안의 번호와 다르다: 예전 1/2/3은 이제 3/4/5다.

## 내보내기

```sh
node preview/exhibition/export.mjs
# PNG 7장(100dpi), 개별 PDF 7개, 혼합 크기의 7쪽 PDF 1개
node preview/exhibition/export.mjs --dpi 150 --panels 4,7 --no-pdf
node preview/exhibition/export.mjs --no-png
node preview/exhibition/export.mjs --variant span   # 실제 화면 시안, out/variant-span/ 에 따로
```

- 서버가 먼저 실행돼 있어야 한다. 포트 기본값은 5203(`--port`), Chrome 경로는 `CHROME` 환경변수로 바꾼다.
- 통합 PDF 병합은 Python의 `pypdf`를 사용한다(`python -m pip install pypdf`).
  Python 실행 경로는 `ORBIT_PYTHON`으로 지정할 수 있다. PNG만 출력할 때는 필요 없다.
- 결과는 git에서 제외된 `preview/exhibition/out/`에 생긴다.
  `orbit-banner-<번호>-<id>.pdf`가 장별 파일(인쇄 원본), `orbit-banners.pdf`는 선택한 장을 모은 검토용이다.
  일부 장만 내보내면 통합 PDF도 그 선택만 포함한다. PNG는 검토용이며 파일에 해상도(pHYs, `--dpi`)를 적는다.
- 내보내기는 `out/`을 비우지 않는다. 출력소에 보낼 꾸러미는 새로 만든 PDF만으로 묶는다(옛 파일을 섞지 않는다):
  `cd preview/exhibition/out && zip orbit-banners-print-<날짜>.zip orbit-banner-?-*.pdf orbit-banners.pdf`.
- `?print=1&panel=all` 또는 `?print=1&panel=1,4,7`은 인쇄 화면이다.
  PDF는 실제 크기의 페이지이며 455mm 두 장에는 별도 페이지 규격을 적용한다.
  내보내기는 PNG 픽셀 크기와 PDF 페이지 수·크기를 확인하고 다르면 실패한다.
- 혼합 폭을 한 번에 브라우저에서 PDF로 저장하면 내용이 자동 축소될 수 있다.
  최종 출력은 내보내기 명령을 사용한다. 개별 PDF를 소프트웨어 렌더링한 뒤,
  통합본은 검증된 파일을 다시 그리거나 축소하지 않고 병합한다.
- 글자는 벡터로, 원근 카드·흐림·그림자는 일부 래스터로 나온다. 글꼴은 Inter, Noto Sans KR,
  JetBrains Mono이며 Google Fonts에서 받는다. 받지 못하면 화면 맨 위에 경고 띠가 찍히고, PDF 내보내기는
  묻힌 글꼴이 이 셋과 아이콘 글꼴(Phosphor)이 아니면 실패한다. PNG만 내보낼 때는 경고 띠를 눈으로 확인한다.
- 출력소의 블리드·CMYK 요구는 아직 미확정이다. 현재 파일은 블리드 없는 재단 크기다.
  PDF를 실제로 렌더링해 글줄·겹침·화면 누락을 확인한 뒤 전달한다.

## 실제 화면 시안(`?variant=span`)

대표 요청(2026-10-23)의 시안이다. 마케팅·디자인팀장 검토(2026-10-23, `~/.cache/orbit-agents/meetings/2026-10-23-banner-copy/`)와
대표 피드백(2026-10-23, B 방향 확정 — 창을 세로로 크게, 아래를 비워 두지 않게, 5번 장을 덜 빽빽하게)을 반영했다. 지금 인쇄판은 그대로 두고 가운데 벽 세 장(3·4·5번)과 6번 TEAM 의 측정 구역 한 줄만 바뀐다.
보기 화면의 `실제 화면 시안`을 켜거나 주소에 `variant=span`을 붙인다(예: `?view=center&variant=span`).

- 세 장에 크롬 창 하나를 이어 건다. 창 안은 실제 새 탭(네비게이터를 연 홈, AI에게 질문)과 사이드패널(세션)이다.
  `span-scene.html`이 미리보기 대역(합성 데이터)으로 두 화면을 띄우고, 사람이 하듯 눌러 상태를 만든다
  (네비게이터 열기·여행 폴더와 제주·오사카 세션·졸업 프로젝트 폴더 펼치기·바로가기 접기·질문 "제주 렌터카 비교하던 거"와
  이어서 "오사카에서 가려던 맛집"·사이드패널 세션 펼치기).
  저장소는 바꾸지 않는다. 장마다 같은 장면을 하나씩 띄워 자기 몫만 보인다.
- 강조 표시는 장면이 잰 요소 자리에 붙는다: ① 첫 질문과 답 상자, ② 그 관련 세션 상자(라벨은 3번 장). 5번 장은 ③④ 라벨
  (제목만) 바로 아래에 그 단추만 2배로 보인 알약 모양 돋보기를 하나씩 두고(③ 열기 두 단추, ④ 공유 단추), 사이드패널의 실제
  단추 줄에 알약 표시 하나만 둔다 — 화살표·테두리 번호·이어 주는 줄은 없다. 돋보기는 위아래 목록 줄과 2px 붙은 이웃 단추를
  담지 않는다.
- 높이: 현수막을 바닥에 세우면 눈높이는 바닥에서 1.5~1.65m(위에서 730~880mm)다. 창 위끝 495mm, 창 높이 1,110px(약 1,066mm)로
  창이 바닥에서 약 0.82m까지 내려온다. 홈은 질문을 두 번 해서 키운 창의 아래쪽까지 실제 대화가 이어지고, 답이 나오면 대화 끝으로
  스크롤한 자리에서 위의 행성 그림이 다 지나가 첫 질문이 r2 와 같은 자리(① 상자 위끝이 바닥에서 약 1.58m)에 온다 — 창을 더
  키우면 스크롤이 모자라 그림이 반쯤 잘려 보인다(`scrollPastOrbit`이 막는다). 창 아래는 숫자 띠가 바닥글 위까지 채운다(숫자는
  칸 위에 붙어 세 장의 선이 맞고, 각주는 칸 아래). `tests/unit/exhibition-span.test.ts`가 높이·안전 여백·돋보기 범위를 지킨다.
- 크기: 장면 1px = 0.96mm. 홈 대화 칸(920px)이 4번 장 안에 들어가고, 네비게이터와 사이드패널을 같은 폭(380px)으로
  둬서 장 경계(기둥 40mm)가 빈 바탕에 떨어진다. 왼쪽 벽(2번)은 모서리를 돌아 이어지지 않아 쓰지 않았다.
- 장 표지: 가운데 세 장은 한 장(02 ORBIT)이고 진행 표시는 USE · ORBIT · TEAM 이다(`frame.tsx` `Chapters`).
- 숫자: 아래 띠는 기술 현수막의 시험 숫자(`PROVEN_STATS`)를 장마다 하나씩 쓴다. 기술 현수막이 빠지므로 검색 지연 숫자는
  6번 TEAM 측정 구역에 한 줄로 남긴다(`TeamBanner latency`, 실측일 때만 숫자). 파이프라인 그림은 앞면에 옮기지 않는다
  (2번 USE 의 네 단계가 같은 이야기를 한다).
- 글꼴과 움직임: 화면 속 제품 글자는 현수막 글꼴(Inter·Noto Sans KR)로 고정한다 — 제품 글꼴 설정은 웹 글꼴이 없으면 시스템
  글꼴로 떨어져 인쇄 PDF 에 묻히고 컴퓨터마다 글줄이 달라진다. 장면 안의 애니메이션·전환은 끈다(인쇄의 가상 시간에서 답 칸이
  떠오르기 전 모습으로 찍혔다).
- 인쇄: `node preview/exhibition/export.mjs --variant span`이 `out/variant-span/`에 따로 낸다(쪽 크기·글꼴 검사 그대로).
  장면이 iframe 이라 PDF 에서 화면 글자도 벡터로 나간다. 크롬은 iframe 의 조상에 `zoom`이 걸리면 iframe 을 PDF 에 그리지 않아,
  이 장만 `transform: scale`로 실제 크기를 맞춘다(`exhibition.css` 끝).
- 화면은 장면이 다 그려진 뒤(`data-ready`) 찍는다. 장면 iframe 은 누를 수 없게 막아 두었다(장마다 다른 상태가 되지 않게).

## 승인된 자산과 QR

- 카드 속 페이지 화면은 공개 웹페이지 캡처다(대표 2026-10-22 — 앞선 "타사 화면 제외"를 대신한다).
  `SHOT_SCALE=2 node preview/capture-shots.mjs`가 새 임시 프로필(로그인·쿠키 없음)의 헤드리스 크롬으로
  `fixtures.ts`의 주소를 1000 × 1600 창에서 찍는다. 카드는 화면 위쪽(폭의 1.17배 높이까지)만 보이므로,
  화면 아래에 붙는 쿠키 안내·앱 설치 띠는 어느 카드에도 들어오지 않는다. 결과 `preview/shots/`는 git에 올리지 않는다.
- 제외 기준은 "카드에 보이는 자리에 있는가"다. 흐린 뒤쪽 카드도 실제 크기로는 수십 cm다.
  사람 얼굴이 크게, 광고("광고" 표시 상품 줄·후원사 광고 포함), 동의·할인 팝업과 안내 말풍선, 남의 작품(디자인 모음·작가 표지·
  썸네일 그림), 홍보 배너·혜택 띠, 덜 그려진 화면은 `content.ts`의 `EXCLUDED_SHOTS`로 뺀다.
  뺀 페이지는 CHAOS·ORBIT 갤러리·TEAM 카드에 아예 두지 않는다(`printable`). 타임라인 글줄에는 남는다.
- 같은 사이트의 깨끗한 화면이 있으면 그것을 찍는다(`capture-shots.mjs`의 `ALTERNATE` — 모바일 블로그 검색, 좌표가 든 지도,
  숙소 상세). 화면 한 부분만 깨끗하면 `content.ts`의 `SHOT_FOCUS`로 그 부분만 키워 보인다(네이버 항공권, 야놀자, 다이닝코드).
  `tests/unit/exhibition-content.test.ts`가 목록과 잘라 쓰는 범위를 지킨다.
- 다시 찍으면 화면이 바뀔 수 있다(광고·팝업·회전 배너). 출력 전에 100dpi PNG를 큰 카드는 원본 크기, 나머지는 2배로
  확인하고, 인쇄에 들어간 사이트 목록을 남긴다. 인쇄에 쓴 화면과 증빙은 `~/.cache/orbit-agents/exhibition-print/`에
  해시와 함께 둔다.
- Orbit 마크는 제품의 `public/orbit-mark.png`를 쓴다. 팀 이름은 Orbit, 팀원 이름은 넣지 않는다.
- 행사 로고는 대표의 마지막 지시에 따라 제외한다. 나중에 추가할 경우 `frame.tsx`에서 공통 배치를 검토한다.
- QR은 7번 띠에 **100 × 100mm** 스티커 칸이다. 어두운 띠 위에서도 읽히게 둘레 16mm 흰 여백을 둔 132mm 흰 판 안에 있다
  (`booth.ts` `qr`, `qrMargin`). 대표가 만든 QR 스티커를 붙이며 임의 주소·가짜 QR을 넣지 않는다.
- 행동 유도는 같은 말로 세 곳에 둔다: 7번 QR 위 "QR로 설치하고 지금 써 보세요"와 아래 "시연은 가운데 노트북에서",
  1번 띠 메시지 아래, 2번 USE 첫머리(실제 화면 시안은 5번 장에도). 가운데 벽 앞에 시연 노트북(대표 노트북, 데모 대본)이 있다는
  전제다 — 시안에서는 가운데 벽이 화면이 되므로 "화면" 대신 기기 이름으로 부른다.
- 경쟁 제품 이름은 비교 그래프의 텍스트로만 쓴다. 사이트 화면·로고 사용과 구분한다.

서버 지연은 HTTP·인증·화면 표시를 제외한다. 리랭킹 설정을 켰어도 골든셋의 실제 LLM 호출은 0회였다.

Orbit도 같은 URL·질문·방문 순서/체류 조건으로 실제 UI 시험을 완료했다.
정답 URL 포함 후보 3/6(그중 1건 답변 모순), 부정 거절 2/2, 첫 후보 복원은 목표 4/9와
다른 페이지 5개다. 일반 사용자 정확도나 깔끔한 작업 복원 성공률로 바꿔 쓰지 않는다.
Headless Chrome 확장 방식과 제주항공 403 등 콘텐츠 차이를 명시했다.
합성 검색 벤치마크와 분리하며 제품 간 속도 배수는 주장하지 않는다.

### 전면 배너에 선별한 강점

대표의 후속 요청으로 5번은 전체 비교표 대신 기록 없음 판별 비율을 강조한다.
`negative_garden`, `negative_piano`의 사전 고정 두 질문에 대해 Orbit 100%, Comet 50%,
차이 +50%p다. Comet은 `logged_in_mixed`·`Q` 행만 사용한다. 로그아웃·재시도·Chrome의
단순 빈 결과는 섞지 않는다. 판정 누락·중복·미측정이면 숫자를 표시하지 않고 오류를 낸다.

인쇄면에서 `(2/2)` 같은 분수 표기는 쓰지 않는다. 제목 옆에 소규모 시험임을 표시하고,
아래에 두 질문·각 1회와 실행/콘텐츠 차이를 적는다. 일반 검색 정확도나 전체 제품 우위로
확장하지 않는다. 서버 성능은 A/B/D를 표시한다. C의 골든/holdout 결과, 실패 결과와
전체 비교표는 원본 파일 및 이 문서에 그대로 남긴다.
