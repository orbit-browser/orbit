# Ask AI 복수 탭 후보 선택

**상태:** 완료 (2026-08-07)
**브랜치:** `feat/tab-actions`

## 작업 목표

- 유사한 열린 탭이 여러 개면 임의 자동 이동이나 막다른 오류 대신 최대 3개 후보를 표시한다.
- 사용자가 후보를 클릭하면 탭 ID를 현재 목록에서 다시 검증하고 해당 창으로 이동한다.
- 단일 확실 후보의 기존 자동 이동은 유지한다.
- 새 탭과 사이드패널 Ask UI에서 동일하게 동작한다.

## 현재 상태와 조사 결과

- 의미 resolver는 top-1 점수와 top-2 격차만 반환하며 낮은 격차에서는 후보 ID를 제공하지 않는다.
- extension Ask turn은 문자열 답변과 관련 세션만 저장해 탭 후보를 렌더링할 계약이 없다.
- 명시적 로컬 문자열 매칭은 복수 일치여도 첫 결과로 자동 이동한다.
- 스크린샷의 두 YouTube 탭은 같은 사이트 용도 때문에 의미 점수가 근접해 정상적으로 자동 이동이
  보류됐지만, 사용자가 다음 행동을 할 수 없는 UX다.

## 포함 범위

- backend low-confidence 응답에 score floor를 통과한 상위 후보 ID·점수 최대 3개 포함
- 비이동 또는 후보 자체 점수가 낮은 경우에는 후보를 노출하지 않음
- 로컬 정확 매칭의 복수 결과도 자동 이동하지 않고 후보로 전환
- Ask turn의 탭 후보 상태와 후보 선택 액션
- 선택 시 최신 열린 탭 ID 재검증, 닫힌 탭 오류 처리, 성공 시 후보 목록 제거
- 새 탭·사이드패널 후보 버튼 UI
- backend/extension 테스트, API·IA·시나리오·결정·작업 문서 갱신

## 제외 범위

- 탭 썸네일 캡처
- 후보 순서 수동 변경
- 닫힌 후보 자동 재검색
- 4개 이상 후보의 페이지네이션
- 자연어 탭 닫기·새로고침

## 구현 순서

1. tab resolver 응답에 후보 계약을 추가하고 낮은 점수와 낮은 격차를 구분한다.
2. extension 타입과 Ask turn에 후보 상태 및 선택 액션을 추가한다.
3. 로컬 복수 일치와 의미 복수 후보를 동일한 UI 계약으로 연결한다.
4. 새 탭과 사이드패널에 제목·호스트가 보이는 후보 버튼을 렌더링한다.
5. 단위·API·타입·빌드와 실제 두 YouTube 후보 HTTP 응답을 검증한다.
6. 관련 문서와 WorkLog를 갱신한다.

## 테스트 및 완료 조건

- 두 개의 YouTube 후보가 유사하면 자동 이동하지 않고 둘 다 표시한다.
- 후보 점수가 절대 기준보다 낮으면 관련 없는 탭 목록을 표시하지 않는다.
- 한 후보가 명확하면 기존처럼 즉시 이동한다.
- 클릭 직전 닫힌 탭은 활성화하지 않고 오류를 표시한다.
- backend/extension 전체 검증과 실제 API smoke가 통과한다.

## 완료 결과

- 실제 두 YouTube와 GitHub 후보에서 자동 이동을 보류하고 YouTube 후보 2개만 반환했다.
- 로컬 복수 매칭과 의미 복수 후보 모두 동일한 Ask 후보 선택 UI로 연결했다.
- 클릭 직전 탭 ID 재검증과 닫힌 탭 오류 처리를 추가했다.
- 관련 backend 테스트 11개, extension 테스트 18개와 TypeScript 검사가 통과했다.
- 전체 회귀는 backend 328개, extension 87개가 통과했고 Chrome MV3 프로덕션 빌드도 완료했다.
