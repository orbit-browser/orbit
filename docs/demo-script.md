# Orbit 3분 시연 대본과 검증 절차

> 작성: 2026-10-20 · 시연·발표 매니저 표나은 · 내부 검토용 초안
> 구현 대조 기준: `docs/demo-script`, 기준 커밋 `626133a`.
> **현재 판정: 화면 리허설 미완료. 아래 180초는 배정 시간이며 실측 기록이 아니다.**
> 대외 발표 문구는 디자인팀장 검토와 대표 승인 뒤 사용한다. `ppt.md` 원문과 모델 표기는 변경하지 않았다.

## 1. 시연 범위와 판정 원칙

- 대표 노트북에서 `./dev.sh`로 운영하는 `http://localhost:8000`을 두 Chrome 프로필이 함께 사용한다. 공용 서버 배포·다른 기기 접속을 시연한 것으로 말하지 않는다.
- 프로필 A는 공개 자료를 탐색하고 세션을 공유하는 사람, 프로필 B는 초대받아 읽는 사람이다. 서로 다른 Google 계정을 사용한다. 시크릿 창·Edge·Aside·Safari로 대체하지 않는다.
- 팀 기능은 **세션 공유형 1단계**다. 공유는 원본 세션의 라이브 참조이며 이후 그 세션에 추가되는 페이지도 포함된다. 팀원은 읽기 전용이고, 개인 전체 방문 기록이나 공동 편집을 보여주는 기능이 아니다.
- 개인 기능은 새 탭 홈·Ask와 기존 사이드패널의 타임라인·세션을 사용한다. 팀 기능은 사이드패널 설정·팀 세션·팀 Ask와 새 탭 아틀라스를 사용한다. 새 탭 설정에 팀 관리 메뉴가 있다고 안내하지 않는다.
- `화면 확인`은 실제 Chrome 확장에서 클릭 후 기대 결과까지 본 경우만 쓴다. 소스·자동화 테스트·빌드 확인은 별도 근거다. 실제 화면을 보지 못한 단계는 모두 **미확인**으로 남긴다.
- 온보딩의 예시 세션·mock 타임라인은 실제 수집 결과로 보여주지 않는다. 사전 결과를 사용할 때는 실제 리허설에서 만들어진 자료인지 확인하고 “사전에 처리한 결과”라고 말한다.

확장 비활성 상태와 시연 계정 미지정 때문에 이번에는 제품 화면을 검증하지 못했다. 서버를 재시작하거나 새 서버를 만들지 않았다. 기존 개인 프로필의 수집 설정·인증·방문 데이터도 변경하지 않았다.

## 2. 시연 전 점검표

이 표는 준비 담당자가 채운다. 현재 체크하지 않은 항목은 통과로 간주하지 않는다.

- [ ] **빌드 고정:** 두 프로필의 확장 버전·확장 ID·로드 경로와 빌드 대상 커밋을 기록한다. `pnpm build` 통과와 설치된 확장이 같은 빌드라는 확인을 분리한다. 생성 파일은 커밋하지 않는다.
- [ ] **서버·도커:** 대표가 띄운 서버와 PostgreSQL·Qdrant가 살아 있고 로그인 후 세션 조회·검색이 된다. 이미 실행 중인 `localhost:8000`은 끄거나 재기동하지 않는다. 연결 실패를 복구한다며 `docker compose down -v`를 실행하지 않는다.
- [ ] **두 Chrome 프로필:** A/B가 각각 별도 Google 계정으로 Chrome과 Orbit에 로그인했다. 새 탭 홈과 사이드패널을 모두 열어 같은 계정의 기록인지 확인한다. 계정 주소·아바타·기존 바로가기가 발표 화면에 노출되지 않게 시연 전용 계정을 쓴다.
- [ ] **OAuth:** 담당자가 Chrome 확장용 OAuth 클라이언트의 항목 ID가 설치된 확장 ID와 맞는지, 확장과 백엔드가 같은 클라이언트를 사용하는지 확인한다. 동의 화면이 테스트 상태면 A/B 모두 테스트 사용자로 등록됐는지 확인한다. 실제 로그인으로 판정하며 키·토큰·환경 파일은 열거나 화면에 띄우지 않는다.
- [ ] **빈 OAuth 설정 구분:** `extension/wxt.config.ts`는 클라이언트 ID가 없어도 빌드가 통과하도록 돼 있다. 빌드 성공만으로 로그인 준비 완료라고 하지 않는다.
- [ ] **수집 동의:** A는 시연 전용 프로필에서만 `탐색 기록 수집`을 직접 켠다. 공개 문서 본문을 근거로 질문할 경우 `본문 저장`도 확인한다. 자동 동기화는 기본 off이며, 이번 리허설은 수동 `세션 분류`로 시작 시점을 고정한다.
- [ ] **합성 시나리오:** §3의 공개 문서만 수집했다. 자동 생성된 S1의 제목·요약·페이지 목록·탐색 타임라인과 검색 가능 상태를 실제로 확인했다. 개인정보·로그인 URL·다른 작업 탭이 섞이지 않았다.
- [ ] **격리 대조군:** 공개 CSS 문서만 담은 별도 개인 세션 S2를 준비해 공유하지 않는다. 개인정보 대신 이 자료로 팀 범위 분리를 확인한다.
- [ ] **라이브 팀과 예비 팀:** 이번 회차의 새 팀 이름을 정한다. 별도 예비 팀 T0는 A/B가 미리 참여하고 S1 공유·해제까지 검증한다. 본 시연 시작 전 T0에서 S1을 공유 해제한다. 예비 팀 준비가 안 됐으면 장애 때 팀 단계 전체를 생략한다.
- [ ] **네트워크:** 노트북 전원·절전·Wi-Fi, 공개 문서 접속, Google 로그인, 임베딩·답변 생성의 실제 성공을 확인한다. localhost 서버만 살아 있는 상태를 인터넷·모델 정상으로 간주하지 않는다.
- [ ] **실측:** §5에서 로그인 A/B, 동기화, 개인 Ask, 팀 Ask의 시작·종료를 기록한다. 질문 전송 후 첫 답변 본문까지의 시간과 답변 완료까지의 시간을 나눈다.
- [ ] **화면 준비:** A 홈·사이드패널, B 팀 설정·아틀라스 탭을 준비한다. 알림을 가리고 프로필 전환 동작을 리허설한다. 초대 코드 전달은 같은 노트북에서 복사·붙여넣기로 끝낸다.
- [ ] **3분 드라이런:** §4를 스톱워치로 한 번 완주한다. 시간을 넘기면 §4의 생략 규칙을 적용해 다시 확인한다. 실패·생략한 단계를 성공으로 채우지 않는다.
- [ ] **발표 승인:** 마지막 절의 `ppt.md` 정정안은 디자인팀장 검토 및 대표 승인을 받는다. 모델 확인 목록은 CTO의 별도 확정 전까지 그대로 둔다.

## 3. 개인정보 없는 탐색 시나리오와 질문

가상의 “오프라인 메모 앱을 위한 브라우저 저장 방식 조사”다. 사람·회사·실제 업무 데이터는 만들거나 넣지 않는다. 아래 URL은 2026-10-20 웹 조회로 페이지 존재를 확인했으며 **Orbit에서의 수집·분류·질문 성공은 미확인**이다.

| 구분 | 실제 방문할 공개 페이지 | 역할 |
|---|---|---|
| S1-1 | [MDN Web Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API) | 저장 API 조사 시작 |
| S1-2 | [MDN IndexedDB API](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) | 구조화 데이터·비동기 작업을 비교할 근거 |
| S1-3 | [MDN Storage quotas and eviction criteria](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) | 저장 공간·제거 조건을 확인하는 후속 탐색 |
| S2 | [MDN CSS grid layout](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout) | 공유하지 않는 별도 개인 세션의 대조 자료 |

### 데이터 준비 순서 — 발표 3분에 포함하지 않음

1. A에서 수집 동의와 본문 수집 설정을 확인하고 S1-1 → S1-2 순으로 방문한다. 페이지가 로드된 뒤 각 20~30초 읽고 스크롤한다. 이 체류시간은 재현을 위한 준비값이며 제품의 세션 생성 보장 조건은 아니다.
2. 사이드패널 `타임라인`에서 제목·시각·도메인과 `대기` 배지를 확인하고, 날짜 헤더의 `세션 분류`를 누른다. 버튼은 대기 기록이 있을 때 표시된다. `세션 분류를 요청했어요` 알림은 요청 전달만 뜻한다. 세션 배지는 이름 대신 아이콘이며, 이름은 툴팁으로 확인한다.
3. `세션` 목록에 조사 세션이 생기고 요약·페이지가 준비되는지 기다린다. 생성된 제목을 그대로 기록해 S1이라고 부른다. 분류가 보류되거나 다른 세션에 붙으면 페이지 구성을 확인하고 리허설 실패로 기록한다. 스냅샷 저장으로 대체한 뒤 자동 생성이라고 말하지 않는다.
4. S1-3을 이어서 방문·분류해 기존 S1에 붙는지 확인한다. 별도 세션이 생기면 “자동 성장 확인”은 미확인으로 남긴다. 라이브 참조 검증 때는 **공유 후 같은 S1에 새 페이지가 추가됐는지**도 별도로 확인한다.
5. S2는 S1과 분리된 탐색으로 준비한다. 필요한 경우 시간 간격을 두고 수집한다. 실제로 별도 세션이 만들어졌는지 확인하며, S1에 섞였으면 공유하지 않고 준비를 다시 한다.
6. A 개인 범위에서 아래 검색·질문과 S1의 근거를 확인한다. B는 팀 참여 후 S1만 보이는지 확인한다. 사전 답변을 쓰려면 해당 질문·범위·실행 시각을 기록한다. 현재 확보된 사전 답변이나 녹화는 없다.
7. 시작 직전에는 S1이 공유되지 않은 상태, A의 범위는 `개인`, B의 Ask는 새 대화 상태로 맞춘다. 실제 사용자 세션을 삭제하거나 DB를 초기화해 상태를 맞추지 않는다.

### 질문 카드

| 용도 | 그대로 입력할 문장 | 확인할 결과·실패 기준 |
|---|---|---|
| 의도로 세션 찾기 Q1 | `오프라인 메모 앱의 브라우저 저장 방식을 조사한 세션 찾아줘` | Ask의 세션 찾기 경로에서 S1이 관련 세션으로 나온다. 제목을 정확히 입력하는 검색과 구분한다. 웹 검색 결과나 열린 탭 이동은 성공이 아니다. |
| 개인 Ask Q2 | `조사한 자료에서 Web Storage와 IndexedDB는 작업 처리 방식과 저장할 데이터 측면에서 어떻게 달랐어?` | 저장된 S1을 근거로 답변·관련 세션을 확인한다. MDN의 동기/비동기 설명 및 저장 데이터 설명과 대조한다. 정확한 답변 문장이나 점수를 미리 정해 읽지 않는다. |
| 팀 Ask Q3 | `팀에 공유한 브라우저 저장 방식 자료에서 IndexedDB를 검토한 이유를 정리해줘` | B의 팀 범위에서 공유된 S1이 근거로 나온다. 미공유 S2나 B 개인 세션이 근거에 섞이면 실패다. |
| 범위 대조 Q4 — 리허설 전용 | `팀에 공유된 자료에서 CSS Grid 배치 방법을 찾아줘` | S2를 공유하지 않았으므로 S2를 근거로 인용하지 않아야 한다. 답변 텍스트만으로 권한 격리를 입증하지 말고 근거·목록·재조회 결과를 함께 확인한다. |
| 기록에 없는 질문 Q5 — 리허설 전용 | `이 팀이 정한 메모 앱 출시일은 언제야?` | 준비 자료에 출시일은 없다. 특정 날짜를 만들어 내면 실패로 기록한다. |

새 탭의 기본 `검색`은 웹 검색/주소 이동이다. Q1·Q2는 **`AI에게 질문`**으로 바꿔 보낸다. 타임라인 돋보기의 `제목·사이트로 걸러내기`와 아틀라스 목록 필터를 의미 검색으로 소개하지 않는다. 팀 Ask는 `workspaceId`를 전달하는 **사이드패널 하단 질문 입력창**에서 실행한다. 이 기준 버전의 새 탭 홈 Ask에는 팀 범위 인자가 연결돼 있지 않다.

## 4. 3분 발표 대본

**사전 조건:** §2·§5를 통과한 실제 빌드, 로그인된 A/B, 준비된 S1과 S2, 예비 팀 T0. 아래 문장은 기대 결과를 실제로 확인한 경우에만 읽는다. 각 행의 시간 한도가 되면 대처 문구로 넘어간다. 대본 전 단계의 현재 화면 판정은 **미확인**이다.

### 진행자가 지킬 생략 규칙

- 종료 시각은 고정한다. 기다린 시간을 뒤 행에 더하지 않는다. 먼저 아틀라스 세부 탐색·답변 전문 낭독을 생략한다. 실패한 선행 단계가 있으면 그 결과에 의존하는 후속 단계도 생략한다.
- T0를 쓸 때 “오늘 사용할 팀”은 A/B 양쪽에서 T0로 맞춘다. 새 팀에 공유하고 예비 팀에서 찾는 실수를 피한다. 팀이 없으면 범위 선택기가 보이지 않는 것이 정상이다.
- D06–D08은 생성→발급→참여를 보여주는 기본 대본이다. 사전 참여로 건너뛴 경우 이 세 단계의 라이브 성공을 주장하지 않는다.
- 동기화 요청, 로컬 대기 수 감소, 요약 준비, 검색 가능은 서로 다른 완료 시점이다. 요청 알림이나 로컬 전송 상태만 보고 자동 세션 생성·색인 완료라고 말하지 않는다. 현재 `동기화됨`·`제외됨` 상태는 배지로 그리지 않으므로 해당 문구가 나타나길 기다리지 않는다.
- 팀 목록에는 15초 폴링이 있지만 아틀라스에는 같은 주기 폴링이 없다. 팀 목록은 전면에서 다음 폴링 결과를 확인하고, 아틀라스는 해당 탭에서 Chrome 새로고침을 누른다. 범위 왕복·창 전환만으로 재조회가 보장되지는 않는다. 라이브 시간 한도까지 갱신되지 않으면 생략하고 §5에서 다시 검증한다.
- “모든 화면에서 즉시 사라진다” 대신 “다시 조회해 확인한다”고 말한다. 과거 화면·이미 받은 Ask 답변을 원격으로 회수하는 기능으로 소개하지 않는다.
- API 오류·빈 결과·부분 답변은 그 상태대로 설명한다. 장애 시 준비한 실결과·실녹화를 쓰려면 현재 라이브 화면이 아니라는 사실과 기록 시각을 밝힌다. 이번 작업에서는 대체 녹화를 만들지 않았다.

### 시간 측정 방법

동일 노트북·빌드·시연 데이터로 로그인은 A/B 각 1회, 동기화와 각 Ask는 가능하면 3회 측정한다. 반복 결과는 각각 적고 성공한 빠른 회차만 골라 평균을 내지 않는다. 이미 로그인된 상태를 새 로그인처럼 재지 않는다.

- 로그인: `Google 계정으로 계속` 클릭부터 홈과 인증된 세션 조회까지. 계정 선택·동의에 쓴 시간도 포함하고 별도 메모한다.
- 동기화: `세션 분류` 클릭부터 ① 타임라인 분류 배지 ② 세션/요약 표시 ③ Q1로 검색 가능까지 따로 잰다. 로컬 `lastSyncAt`은 전송 시점일 수 있어 최종 완료 기준으로 쓰지 않는다.
- Ask: `질문 보내기`부터 **답변 본문 첫 글자**까지와 **생성 종료 및 근거 표시**까지를 나눠 잰다. 로딩 표시·근거 카드만 나타난 시점은 첫 답변 본문이 아니다. Q1의 세션 찾기 경로는 답변 생성 지연 측정에서 제외한다.
- 사전 측정 관찰 한도: 로그인 60초, 동기화 300초, Ask 60초. 이는 진행자 운영 한도이며 제품 SLA·타임아웃 값이 아니다. 초과하면 `>한도, 미완료`로 적는다. 라이브 대본의 한도는 §4처럼 더 짧다.
- 모델은 실행 화면/비밀 없는 메타데이터로 확인한 식별자만 기록한다. 확인할 수 없으면 `미확인`. 요청 본문·Authorization·초대 코드 원문은 저장하지 않는다.

| 대상·회차 | 시작 시각 | 첫 본문/분류 배지까지 | 완료/요약까지 | 검색 가능/근거 | 결과·모델·메모 |
|---|---|---|---|---|---|
| 로그인 A / B | 미측정 | 해당 없음 | 미측정 | 미확인 | 시연 프로필 미지정, 화면 미확인 |
| 동기화 1 / 2 / 3 | 미측정 | 미측정 | 미측정 | 미측정 | 실제 수집·분류 미실행 |
| 개인 Ask Q2, 1 / 2 / 3 | 미측정 | 미측정 | 미측정 | 미확인 | 실모델·근거 미확인 |

자동화 테스트는 이 표의 실제 화면·시간 측정을 대신하지 않는다. 표를 채우기 전에는 “전 단계 시연 검증 완료”, “3분 완주”, “몇 초 이내 답변”이라고 발표하지 않는다.
