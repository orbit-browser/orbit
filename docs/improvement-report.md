## 1. 1차 안정화 완료

### H1/M4. AI 요약 실패가 성공으로 기록되는 문제

**상태: ✅ 완료**

- `generate_summary`의 catch-all fallback을 제거했다.
- LLM/파싱 오류를 `_ai_update`까지 전파해 `summary_status=failed`로 기록한다.
- 공백 또는 누락된 `overview`도 실패로 처리한다.
- 최초 저장 응답의 규칙 기반 제목과 임시 요약은 유지한다.
- 실패한 AI 요약은 Qdrant 임베딩 단계로 넘어가지 않는다.

효과: 재시도 UI가 실제 실패 경로에서 동작하고, 더미 요약의 검색 인덱스 오염을 막는다.

### H2. 상세 화면 pending 캐시 고착

**상태: ✅ 완료**

- Extension pending 폴러가 완료/실패 시 `['sessions']`와 `['session', id]`를 모두 무효화한다.

효과: 상세 화면을 열어둔 상태에서도 스피너가 완료 또는 실패 상태로 전환된다.

### H3. Backend 전체 장애가 빈 검색 결과로 보이는 문제

**상태: ✅ 완료**

- 검색 API 실패 후 세션 목록 기반 로컬 검색은 계속 유지한다.
- 세션 목록 조회까지 실패하면 React Query 오류 상태를 검색 화면에 전달한다.
- 연결 오류를 “관련 세션 없음”과 구분해 표시한다.

### H4. 민감 도메인 필터와 과도한 권한

**상태: ✅ 완료**

- `toss.im`, `kebhana.com`, `ibk.co.kr`, `citibank.co.kr`, `kakaobank.com`, `kbanknow.com`, `tossbank.com`, `kakaopay.com`, `payco.com` 등을 보강했다.
- 일반 학회·협회까지 차단하던 `.or.kr` 전체 패턴을 제거했다.
- 명시된 금융/의료 기관과 `.go.kr` 차단은 유지한다.
- 사용하지 않는 Chrome `bookmarks` 권한을 제거했다.

주의: 도메인 목록은 운영 전 실제 사용 로그가 아닌 공식 hostname 기준으로 한 차례 더 점검하는 것이 좋다.

### M1. 기동 복구 작업 폭주와 task 참조 유실

**상태: ✅ 완료**

- pending 요약과 임베딩 복구를 하나의 coroutine에서 순차 실행한다.
- 복구 task를 모듈 수준 set에 보관하고 완료 시 제거한다.
- 서버 시작 응답은 복구 완료까지 기다리지 않는다.

효과: 외부 API 호출 제한 초과 가능성을 줄이고 task가 중간에 유실되지 않는다.

### L1. 100자 초과 제목 PATCH 오류

**상태: ✅ 완료**

- `PatchSessionRequest.title`에 `max_length=100`을 추가했다.
- 100자는 허용하고 101자는 Pydantic 검증 단계에서 거부한다.

## 3. 다음 구현 우선순위

### P1. 발표자료와 실제 구현 정합화

**우선순위: High · 예상 2~3시간**

- `ppt.md`의 “HDBSCAN + cosine similarity”를 Solar Mini LLM 클러스터링으로 수정한다.
- “Structured Output” 표현을 현재의 JSON 지시, 파싱, 검증, fallback 구조에 맞춘다.
- 실제 파이프라인 순서인 `LLM 클러스터링 → 요약 → passage 임베딩 → Qdrant 검색 → 선택적 리랭킹`을 다이어그램으로 정리한다.
- 임베딩 클러스터링을 실험 후 기각한 근거를 설계 판단으로 설명한다.

### P2. 검색 정확도와 오류 계약

**상태: ✅ 기반 구현 완료 · threshold 실측 튜닝 대기**

- Qdrant `score_threshold`를 환경변수로 추가하고 기본값 `0.35`를 적용했다.
- 신규·재처리 세션의 임베딩 입력에 세션 제목을 포함한다.
- 임베딩 timeout, 연결 실패, upstream 오류, 응답 형식 오류를 구분한다.
- Qdrant 장애를 안전한 503 응답으로 변환한다.
- 기존 Qdrant 포인트 자동 재색인은 포함하지 않았다.

남은 검증:

- 실제 세션/검색어 골든셋으로 `0.35`의 precision과 recall을 측정한다.
- 무관한 쿼리와 제목 중심 쿼리를 포함해 threshold를 재조정한다.

### P3. 세션 복원 부분 실패 처리

**우선순위: Medium · 예상 1시간**

- `Promise.allSettled`로 탭별 실패를 격리한다.
- 성공/실패 탭 수를 토스트에 반영한다.
- 많은 탭을 열기 전 확인 단계를 제공한다.

### P4. 대시보드 검색 안정화

**우선순위: Medium · 대시보드를 데모에 사용할 때**

- 검색 오류와 degraded 상태를 Extension과 일치시킨다.
- 입력 호출에 300~500ms debounce를 적용한다.
- Extension과 Frontend에 중복된 API 타입/매퍼의 단일 출처화를 검토한다.

## 4. 분류 고도화 설계

### D1. 세션 기준 확장

현재 분류는 제목과 URL의 주제 유사성을 중심으로 한다. 다음 단계에서는 아래 축을 함께 사용한다.

- 작업 의도: 무엇을 하려던 탐색인가
- 탭 그룹: 사용자가 직접 만든 그룹은 강한 제약으로 취급
- opener 관계: 같은 탐색 트리인지 판단
- 마지막 접근 시간: 같은 시간대 작업인지 판단

구현 전 결정할 사항:

- 큰 주제와 세부 작업 중 어느 단위로 세션을 나눌지
- 현재 창만 저장할 때 의미가 없는 `windowId`를 포함할지
- 그룹 제목을 위해 `chrome.tabGroups` 권한을 추가할지

### D2. LLM 클러스터링 유지

임베딩 기반 방식은 짧은 제목/URL과 작은 표본에서 불안정했고, 그룹명 생성을 위해 LLM이 다시 필요했다. 따라서 Solar Mini 기반 클러스터링을 유지한다. 임베딩은 세션 검색과 향후 세션 병합 후보 탐색에 사용한다.

### D3. 프롬프트 및 누락 탭 처리

- 제목이 약한 탭을 위해 안전한 `excerpt` 일부를 추가한다.
- 1탭 그룹 남발 금지와 작업 의도 기준을 프롬프트에 명시한다.
- LLM 누락 탭과 `_MAX_TABS` 초과 탭은 정상 그룹에 섞지 않고 “기타”로 분리한다.
- 실제 브라우징 스냅샷과 사람이 만든 정답 그룹으로 골든셋을 만든다.
