# Orbit 정보 구조

## -1. 로그인 (2026-08-07 신규)

로그인은 **필수**다. 구글 계정으로만 가입·로그인하며, 비밀번호는 저장하지 않는다.
로그인 전에는 사이드패널과 새 탭 어느 화면도 열리지 않고, 백엔드 API 는 모두 401 을 돌려준다.

### 화면

- **새 탭 로그인 화면** — Orbit 마크 + 안내 + `Google로 계속하기` 버튼 하나
- **사이드패널 로그인 게이트** — 같은 구성의 축소판

두 화면 모두 저장된 세션을 읽는 동안에는 빈 화면을 유지한다(로그인 화면 깜빡임 방지).

### 흐름

```
Google로 계속하기
   ↓  chrome.identity.getAuthToken (크롬 프로필 계정)
access token
   ↓  POST /auth/google
백엔드: tokeninfo 로 검증 (aud == 우리 client_id) → 사용자 조회/생성 → JWT 발급
   ↓
chrome.storage.local 에 세션 저장 → 이후 모든 API 호출에 Authorization 헤더
```

- 처음 들어온 구글 계정이면 **그 순간이 가입**이다(별도 가입 화면 없음).
- 최초 가입자 한 명에 한해, 인증 도입 전 쌓인 데이터를 그 계정으로 이관한다.
- 401 응답을 받으면 저장된 세션을 지우고 재로그인을 요구한다.

### 로그아웃

- 새 탭: 우측 상단 프로필 메뉴 > 로그아웃
- 사이드패널: 설정 > 계정 > 로그아웃

저장된 세션과 크롬의 구글 토큰 캐시를 함께 비운다 — 캐시를 남기면 다음 로그인에서
계정 선택 없이 같은 계정으로 조용히 다시 들어간다.

## 0. 새 탭 홈 · 아틀라스 (신규 — 2026-08-07)

익스텐션이 `chrome_url_overrides.newtab`으로 크롬 새 탭을 대체한다. 브라우저를 열었을 때
가장 먼저 만나는 화면이며, `orbit_front` 시안의 두 화면을 그대로 이식했다.
탭 이름은 크롬 기본과 같은 `새 탭`.

두 화면은 해시 라우트로 전환한다.

| 라우트 | 화면 |
| --- | --- |
| `newtab.html` (또는 `#/`) | 홈 |
| `newtab.html#/orbit-atlas` | 아틀라스 |

`#/orbit-atlas?session=&page=` 로 선택 상태를 URL에 실어 새로고침에도 같은 화면이 뜬다.
좌측 네비게이터의 열림·너비·펼침·선택 상태는 두 화면이 공유한다(`lib/nav-state.ts`) —
화면을 오가도 네비게이터는 그대로 있고 오른쪽 내용만 바뀐다.

네비게이터는 **닫힌 상태가 기본**이다. 새 탭은 브라우저 시작 화면이므로 드로어가 펼쳐진 채
뜨면 방해가 된다. 상단 바 토글로 열며, 연 상태는 그 탭 안에서만 유지된다(새 탭마다 초기화).

예외로 **히어로의 Orbit 그래픽을 눌러 대시보드로 갈 때만** 네비게이터가 펼쳐진 채 열린다.
이 경로는 특정 세션이 아니라 대시보드 전체를 둘러보러 가는 입구이기 때문이다.
카드·타임라인에서 특정 세션으로 들어갈 때는 오른쪽 내용에 집중하도록 닫힌 채 둔다.

### 홈

- **상단 바** — 네비게이터 토글, 유저 메뉴(플랜·설정 항목 드롭다운)
- **좌측 네비게이터 드로어** — Session → Page 트리. 검색, 항목 펼침/접힘
- **히어로** — 시그니처 Orbit 그래픽(클릭 시 아틀라스로), 검색창, 바로가기
- **최근 탐색**(좌) — 세션 타임라인. 클릭 시 그 세션의 대시보드로 이동
- **이어서 탐색하기**(우 상단) — 가장 최근 활동 세션
- **다시 볼 세션**(우 하단) — 서버가 여러 신호 + LLM 리랭킹으로 고른 **추천 3개**를
  7초 간격으로 번갈아 보여준다
  - 배지는 추천 성격(`이어가기` / `지금과 연관` / `다시 보기`), 본문 아래에 **추천 이유** 한 줄
  - 추천은 새 탭을 열 때 **한 번만** 조회한다. 캐러셀 회전은 이미 받은 3개를 돌리는 것이라
    추가 API 호출이 없다
  - 서버 추천이 없거나 실패하면 최근 세션으로 대체한다(빈 자리를 남기지 않는다)

두 섹션의 카드 모두 2버튼
  - `상세 보기` → 그 세션의 대시보드로 이동
  - `세션 복원` → 세션의 페이지를 현재 창에 탭으로 되살린다.
    버튼에 마우스를 올리면 `새 창으로 세션 복원` 이 왼쪽으로 펼쳐진다
    (사이드패널과 같은 `lib/chrome-bridge.ts` 구현 재사용)

별도의 세션 상세 모달은 두지 않는다. 세션을 여는 경로는 **대시보드 하나로 통일**했다.

### 아틀라스

- **좌측 네비게이터** — 홈과 같은 부품. Folder → Session → Page 3뎁스 트리와
  `정리 안 됨` 섹션으로 나뉜다
- **캔버스** — 중심 노드 + 동심 궤도. 두 가지 씬을 같은 부품으로 그린다
  - **폴더 씬** — 중심에 폴더, **궤도 한 줄이 세션 하나**. 각 호의 최하단에 세션 칩
    (제목 · `Np · 시간` · 날짜)이 붙고, 호나 칩을 클릭하면 **그 세션의 페이지만** 위성으로
    펼쳐진다. 다시 누르면 접힌다
  - **세션 씬**(미정리 세션) — 중심에 세션, 궤도에 페이지를 `sequence_order` 순서로 배치.
    이벤트가 없는 snapshot 세션은 저장된 탭 순서를 사용한다

폴더 씬에서 모든 궤도의 점을 동시에 그리지 않는 것은 밀도 때문이다. 세션 5개 × 페이지
30개면 점 150개가 겹쳐 개별 점을 겨눌 수 없다. 한 번에 한 세션만 펼치면 화면에 남는
위성이 최대 7개로 유지되고, 나머지 궤도는 칩만으로 무엇이 있는지 알려 준다.
- **하단 트레이** — 선택한 세션의 페이지 카드(체류시간·재방문 수·열기)
- **우측 상세 패널** — 세부 정보, 실제 이벤트 기반 탐색 인사이트, 세션 요약, 작업

#### 궤도의 앞면과 뒤편

한 궤도는 앞면(보이는 반원)에 **슬롯 7개**까지만 놓는다. 각도가 아니라 슬롯으로 세는
이유는 궤도마다 점을 놓을 수 있는 각도 구간이 다르기 때문이다 — 세션 칩이 붙은 궤도는
최하단이 칩 자리라 칩 폭만큼을 비우고 좌우로 갈라 배치한다. 정원(14개)을 넘는 만큼은
**궤도 뒤편에 보관**되어 회전으로만 보인다.

펼친 궤도 아래에 `현재–현재 / 전체` 위치를 표시한다 — 뒤에 얼마가 남았는지 모르면 끝까지
돌려봐야 알 수 있기 때문이다.

궤도 줄이 4개를 넘으면 창 밖 첫 궤도가 화면 아래에 걸친 채 흐리게 남고, 축을 이동하면
그 궤도가 창 안으로 들어온다.

| 조작 | 동작 |
|---|---|
| 궤도 호 · 세션 칩 클릭 | 그 세션의 페이지를 펼침 (다시 누르면 접힘) |
| `←` `→` | 펼친 궤도 회전 (뒤편 항목을 앞으로) |
| `↑` `↓` | 궤도 축 이동 (안쪽 ↔ 바깥쪽) |
| 캔버스 위 휠 | 궤도 축 이동 |
| `Esc` | 선택 해제 |

#### 폴더 정리

- 폴더 생성·이름 변경·삭제는 네비게이터에서 한다. **폴더를 지워도 세션은 지워지지 않고**
  `정리 안 됨`으로 돌아간다
- 세션을 넣는 경로는 두 가지다 — 폴더 행의 `+`(다중 선택 후 일괄 추가)와 세션 드래그앤드롭.
  드래그만 두면 포인터를 못 쓰는 사용자가 정리를 할 수 없어 `+` 경로가 동등한 대체 수단이다
- 세션은 폴더 하나에만 속한다. 다른 폴더에 있던 세션을 넣으면 이동이며, 일괄 추가
  대화상자가 미리 "○○에서 이동"으로 알려 준다
- **검색은 폴더 계층을 무시하고 평면 결과를 낸다.** 잘못 넣어 둔 세션도 검색으로는 반드시
  나와야 하며, 결과에는 어느 폴더에 있는지 경로를 함께 표시한다

### 검색창

브라우저 주소창과 같은 규칙으로 동작한다. 판별 규칙은 `extension/lib/omnibox.ts`.

- `http`/`https`/`file` 스킴이 명시되면 그대로 이동
- `localhost[:port]`·루프백 IP는 `http`, 그 밖의 "점 + TLD" 형태는 `https`를 붙여 이동
- 나머지(공백 포함, 점 없음, 허용되지 않은 스킴)는 사용자의 기본 검색엔진으로 검색
- `javascript:`·`data:`·`chrome:` 등은 이동시키지 않고 검색으로 강등
- 실패 시 입력창 아래에 오류 문구를 노출

`Tab` 키로 `검색` ↔ `AI에게 질문` 모드를 전환한다. AI 모드는
`POST /ask/stream`을 호출해 실제 탐색 기록 기반 답변을 점진적으로 표시한다. 각 답변 아래에는
근거로 사용한 관련 세션을 최대 3개까지 번호와 함께 보여주며, 클릭하면 해당 세션의 아틀라스를 연다.
각 질문은 이전 질문·답변을 전달하지 않는 독립 단일턴이다. 질문·답변 카드는 아래로 계속 누적되며,
사이드패널 메뉴 또는 홈·Atlas 사이를 이동했다 돌아와도 같은 extension 문서 안에서는 유지된다.
`새 대화 시작하기`를 누르면 진행 중인 답변을 중단하고 누적 목록을 비운다.
누적 대화 패널은 `AI에게 질문` 모드에서만 보인다. `검색` 모드로 전환하면 대화 상태는
그대로 보존한 채 최근 탐색과 이어서 탐색하기로 구성된 기존 홈 콘텐츠를 다시 표시한다.
“GitHub 탭으로 이동해줘”처럼 정확히 일치하는 입력은 extension 로컬에서 즉시 처리한다.
그 밖의 입력은 통합 의도 라우터가 탭 이동·세션 찾기·전체 기록 내용 검색·특정 세션 내용 검색으로
구분한다. “아까 보던 영상으로 돌아가자” 같은 간접 이동 표현이면 모든 일반 창의 탭 제목·호스트·URL
path를 탭 전용 backend resolver에 보내 의미 유사도를 한 번 더 비교한다.
이동 의도와 후보 점수·격차를 모두 통과한 경우에만 응답 ID를 현재 탭 목록에서 재검증하고,
해당 창을 포커스해 탭을 활성화한다. 낮은 신뢰도면 구체적인 이름을 요청하고 일반 질문이면
의도별 Ask AI 스트리밍으로 이어진다. 세션 찾기는 관련 세션 목록을 최대 5개 표시하고,
내용 검색은 현재 질문과 의미가 가까운 페이지 본문을 근거로 답한다. 실행 결과는 일반 답변처럼 누적된다.
후보 점수는 충분하지만 비슷한 탭이 여러 개면 답변 카드 안에 제목·호스트/경로가 있는 후보 버튼을
최대 3개 표시한다. 사용자가 누른 시점에 탭 ID를 다시 확인하고 이동하며 성공하면 후보 목록을 닫는다.

### 바로가기

검색창 아래, 크롬 기본 새 탭의 그 자리. `바로가기` 라벨을 눌러 펼치고 접으며,
접힘 상태는 저장돼 다음에 열 때도 유지된다.

- 사용자가 편집한 적이 없으면 `chrome.topSites`(자주 방문한 사이트)를 최대 10개 보여준다
- `바로가기 추가`로 이름(선택)과 주소를 직접 등록한다. 주소가 아니면 거부한다
- 타일에 마우스를 올리면 삭제 버튼이 나온다
- 한 번이라도 추가·삭제하면 그때부터 사용자 목록만 쓴다
- 아이콘은 확장 내장 파비콘(`_favicon/`) — 외부 서비스에 방문 기록을 흘리지 않는다

### 데이터 연결과 상태

- 홈과 아틀라스는 `GET /sessions` 및 `GET /sessions/{id}/events`를 React Query로 조회한다
- 페이지 노드는 이벤트의 시간 순서를 유지하며, 같은 URL의 총 방문 횟수를 함께 표시한다
- 이벤트가 없는 snapshot 세션은 `tabs`를 페이지 목록으로 사용한다
- 세션 목록 실패는 재시도 가능한 오류로 표시하고, 빈 목록과 페이지 없는 세션을 구분한다

## 1. Chrome Extension 사이드패널

### 전역 내비게이션 (2026-08-12 개편)

- TopNavBar 세그먼트: **타임라인 / 세션 / 열린 탭** — 우측에 새로고침·설정 아이콘
- 타임라인(기본 진입 화면)
- 세션 목록
- 열린 탭 찾기·북마크(세션 탭 안 접이식에서 독립 탭으로 승격)
- 설정(아이콘 진입, 상단 바가 `설정` 헤더로 바뀜)
- 세션 상세(세션 행 클릭으로 진입, 상단 바는 세션 탭 활성 유지)

### Ask AI (2026-08-12 개편 — 탭에서 하단 상시 독으로)

- 메인 세 탭(타임라인/세션/열린 탭) **하단에 입력창이 항상 붙어 있다**. 세션 상세와 설정에는 없다.
- 질문을 보내면 답변 화면이 현재 탭 위로 올라오고, 상단 바가 `‹ Ask AI` 헤더로 바뀐다.
  헤더 우측에 대화가 있을 때만 `새 대화`가 나온다.
- 답변 화면이 올라와 있는 동안에도 하단 입력창은 자리를 지켜 다음 질문을 이어서 던질 수 있다.
- `‹`로 닫으면 원래 탭으로 돌아간다. 대화 턴은 전역 store에 남아 다시 열면 이어서 보인다.
- 관련 세션 카드에서 세션을 열면 답변 화면은 닫히고 세션 상세로 이동한다.
- 키워드·세션 검색은 별도 화면 없이 이 채팅창이 처리한다(`search_memory` / `search_session` /
  `navigate_tab` 의도 라우팅). 독립 단일턴이며 이전 답변을 참조하지 않는다.
- 빈 상태: 안내 문구 + "아래 입력창에 물어보세요."

### 타임라인 (기본 화면 — 2026-08-12 개편)

**역할: 브라우저 방문 기록의 대체.** "아까 본 거 뭐였지"를 스크롤이나 필터로 즉시 되짚어
다시 들어가는 화면이다. 오래된 기록 탐색은 세션 탭과 Ask가 담당한다.

**시간 범위는 최근 48시간이다.** 목록의 원천이 서버가 아니라 로컬 큐(IndexedDB, 48시간 보관)이고,
서버는 세션 배지를 붙이려고 최대 3일치만 조회한다. 전체 기록 열람으로 넓히려면 백엔드에
기간 조회를 새로 열어야 한다(미결정).

화면 구성(위에서부터):

- **날짜 구분 헤더(sticky)** — 맨 위 그룹의 헤더가 **동기화 상태 줄과 필터 진입점을 겸한다**.
  우측에 미처리 개수(있을 때만 점+숫자), 마지막 동기화 시각, 돋보기 버튼. 상태 전용 카드는
  두지 않는다.
- **필터(접힘 기본)** — 돋보기를 누르면 목록 위에 입력창이 펼쳐진다. 제목·도메인·URL 문자
  일치로 로컬 목록을 즉시 걸러낸다. 네트워크를 타지 않아 아직 동기화되지 않은(`대기`) 기록도
  찾힌다. Ask는 서버에 저장된 것만 찾으므로 "방금 본 페이지"는 이 필터가 유일한 경로다.
  `Esc`나 `✕`로 닫으며, **닫을 때 입력을 비운다** — 접힌 채로 필터가 걸려 있으면 목록이 왜
  짧은지 알 수 없다. 입력창은 날짜 헤더가 아니라 목록 밖에 둔다. 결과가 0건이면 헤더가
  사라져서 헤더 안에 있으면 입력을 고칠 수 없게 된다.
- **이벤트 항목(한 줄)** — 방문 시각 · 파비콘 · 제목 · 체류시간 · 세션 배지(`분류 대기` /
  `동기화됨` / `제외됨` / 세션명). 클릭 시 새 탭으로 열고, hover 시 개별 삭제 버튼이 나온다.
  **도메인은 표시하지 않는다** — 파비콘이 같은 정보를 더 빨리 전달하고 사이트 이름이 제목에
  다시 나오는 경우가 많다. 전체 제목과 URL 은 hover 툴팁으로 확인한다. 체류시간은 분 단위
  위로 초를 버린다(`45초` / `12분` / `2시간`). 세션 상세의 탐색 타임라인도 같은 컴포넌트를
  쓰므로 두 화면의 행 모양이 같다.

수동 동기화(`지금 저장`)는 별도 버튼 없이 **상단 바 새로고침 아이콘에 통합**했다. 누르면
동기화를 요청하고 화면 쿼리도 함께 무효화한다. 요청 실패 시에도 화면 새로고침은 수행하고
그 사실을 토스트로 알린다.

수집 opt-in 안내는 상시 카드가 아니라 조건부다.

- 수집 꺼짐 + 기록 없음 → 안내가 화면 전체를 쓴다(`수집 켜기` 버튼)
- 수집 꺼짐 + 기록 있음 → 목록 위 한 줄 안내(`켜기`)로 축소, 기존 기록은 계속 보여준다
- 수집 켜짐 → 아무것도 그리지 않는다

"이번 주 탐색 분석"(top3 세션·도메인) 카드는 제거했다. 목록이 48시간인데 카드만 7일치라
한 화면 안에서 시간 범위가 어긋나 있었고, 액션으로 이어지지 않는 정보였다.

### 열린 탭 (2026-08-12 — 독립 탭으로 승격)

- 모든 일반 Chrome 창의 탭을 제목·URL로 검색한다
- 각 결과에 창 번호와 활성 상태를 표시한다
- 이동 버튼은 해당 창을 포커스하고 탭을 활성화한다
- bookmark 가능한 웹/파일 탭은 체크박스로 개별 또는 검색 결과 전체 선택한다
- `북마크 N` 버튼은 선택 URL을 Chrome ‘기타 북마크’에 추가한다
- 이미 북마크된 URL과 선택 내 동일 URL은 건너뛰고 결과를 토스트로 알린다

### 세션 목록 (2026-08-12 — 카드 그리드에서 행 리스트로)

수동 저장(`현재 세션` 카드)은 제거했다. 세션화는 이벤트 배치가 담당한다.

- 상단: 병합 제안(있을 때만) — 유사도·겹치는 키워드, 개별 병합과 일괄병합,
  실행 전 확인하며 성공 직후 되돌리기 제공
- 그 아래: **최근순 묶음**(`오늘` / `어제` / `지난 7일` / `지난 30일` / `그 이전`)으로 나눈
  세션 행 리스트. 묶음 기준은 마지막 활동 시각(`lastActivityAt ?? updatedAt ?? createdAt`)이며,
  비어 있는 묶음은 표시하지 않는다. 묶음 헤더는 타임라인 탭과 같은 sticky 라벨이라 두 탭이
  같은 구조로 읽힌다.
- 행 구성(접힘): `세션 색 점` · 세션 제목 · 대표 파비콘 스택(도메인 중복 제거, 최대 3개 +
  우측 고정폭 `+N` 숫자)
- **세션 색**은 새 탭 궤도 캔버스와 같은 팔레트·같은 규칙(`lib/session-hue.ts`)을 쓴다.
  같은 세션이 두 화면에서 같은 색을 가지며, 색은 장식이 아니라 동일성을 나르는 정보다.
  목록에서 원색이 줄줄이 서지 않도록 배경 쪽으로 채도를 눌러 표시한다.
- **행 어디를 눌러도 펼쳐진다.** 색 점은 hover·펼침에서 같은 자리의 화살표로 바뀐다
  (자리를 옮기지 않아 목록이 흔들리지 않는다). 세션 상세로 바로 들어가는 클릭은 없다.
- 행 사이 구분선은 두지 않는다 — 묶음 사이 여백과 hover 배경이 행을 가른다.
- 접힌 행에서도 보이는 상태: 요약 중(스피너 + "AI가 주제 분류 및 요약 중…"),
  요약 실패(파비콘 자리에 `다시 시도` 칩)
- 펼친 영역: 세션 색 헤어라인이 왼쪽을 감싼다(행이 삽입된 게 아니라 서랍이 열린 것으로
  읽히게). 안에는 `N개 탭 · 8/7 22:31` + 이름 바꾸기 → AI 요약 개요 → **방문 시각순 탭 목록**
  → 액션 줄(`새 창에서 열기` / `현재 창에 열기` / `삭제`). 삭제는 확인 후 실행
- **탭 목록은 방문 시각을 함께 보여준다.** 시각은 탭이 아니라 방문 이벤트에만 있으므로
  `GET /sessions/{id}/events` 를 펼친 세션에 한해 조회한다. 이벤트를 그대로 나열하면 같은
  페이지를 세 번 본 세션이 세 줄이 되므로, **페이지 단위를 유지한 채 처음 본 시각과 방문
  횟수(`×3`)만 얹고 시각 오름차순으로 세운다** — 세션 안에서는 "어떻게 시작해 어디로 갔나"가
  읽혀야 한다. 조회가 실패하거나 이벤트가 없는 옛 세션은 시각 없이 기존 순서로 표시한다.
- **이름 바꾸기**는 펼친 영역 메타 줄의 연필 버튼. 인라인 입력이며 `Enter` 로 확정,
  `Esc` 로 취소한다. 세션 상세 뷰에 있던 기능을 목록으로 가져온 것이다.
- 두 열기 버튼은 같은 동작(세션의 탭을 전부 연다)의 두 방식이므로 라벨에 목적지를 적고
  강조로 위계를 준다. 토스트도 버튼과 같은 낱말을 쓴다(`새 창에서 열었어요`)
- 탭 수와 시간은 접힌 행에서 빼고 펼친 영역으로 옮겼다 — 목록을 훑을 때는 제목만 읽힌다.
- 요약 실패는 채운 빨간 배지 대신 조용한 텍스트 버튼으로 둔다 — 차분한 목록에서 실패만
  소리치지 않게.

### 세션 상세

- 세션 제목
- 탐색 개요와 목적
- 핵심 정보
- 미완료 작업
- 다음 행동
- 포함된 탭 목록
- 전체 복원
- 요약 실패 시 재시도
- **탐색 타임라인(신규 섹션)**: 세션에 속한 방문 이벤트를 시간순으로 표시(시각/제목/도메인/체류시간/relevance) — 사용자가 "어떤 흐름으로 이 결론에 도달했는지" 확인할 수 있게 한다. 항목 클릭 시 해당 페이지를 연다. 백엔드 응답에 해당 필드가 있을 때만 표시되어 기존 화면과 독립적으로 배포 가능하다.

### 설정

- 민감 도메인 본문 제외 여부
- 검색 리랭킹 여부
- 백엔드 연결 상태
- **수집·동기화(신규 섹션)**: 수집 마스터 토글(기본 off, opt-in — 최초 활성화 시 안내 문구), 자동 동기화 on/off 및 주기(15/30/60분), 유휴 기준, 개수 기준, 본문 저장 토글, 민감 도메인 제외(기존 항목을 이 섹션으로 이동)
- **세션 관리**: 자동병합 opt-in 토글. 다음 동기화에서 제목까지 거의 같은 명백한 중복만 병합하며 기본값은 off

## 2. Backend API 영역

- 세션 생성 및 클러스터 생성(유지 — "지금 열린 탭 스냅샷 저장" 경로로 존치)
- 세션 목록/상세/수정/삭제
- 요약 재시도
- 자연어 검색 및 선택적 리랭킹
- 상태 확인
- **이벤트 인제스트 및 동기화(신규)**: 배치 이벤트 수신, 미동기화 수 조회, 동기화 트리거, 동기화 상태 조회
- **세션 Timeline·버전 조회(신규)**
- **Intent 검색(scope=memory, 신규)**: 기본값(scope=sessions)은 기존 동작 그대로 유지
- **Exploration Analytics 집계(신규)**
- **이벤트 삭제(신규)**: 개인정보 통제 목적
- **세션 병합**: 제안 조회, 사용자 확인 병합, 되돌리기, 자동병합 설정

## 3. 핵심 정보 관계

```text
브라우저 방문 이벤트
  -> (로컬 큐)
    -> Event Store
      -> 배치 AI 분석
        -> 세션
          -> 요약
          -> Timeline
          -> 검색 벡터
          -> 버전
```

기존 "탭 스냅샷 저장" 경로(`POST /sessions/cluster`)는 별도 진입점으로 유지되며, 이렇게 생성된 세션도 이벤트 기반 세션과 동일한 구조(요약/검색 벡터/버전)를 공유한다.

화면이나 API 흐름을 변경하면 이 문서와 `UserScenarios.md`를 함께 갱신한다.
